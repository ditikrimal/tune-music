# Tune Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native Windows (WPF) YouTube Music player with a Spotify-like dark UI, local personalised feed, no login, floating slim-bar mini-player, tray + media keys, ~≤120 MB RAM.

**Architecture:** `Tune.Core` (plain .NET library, fully unit-tested) holds the YouTube Music InnerTube client + parsers, local SQLite library, queue engine, feed builder, stream resolver (bundled yt-dlp + deno), SponsorBlock client and the `PlaybackService` that orchestrates them behind interfaces. `Tune.App` (WPF) holds the libmpv audio player, views, mini-player, tray and SMTC. UI binds to `PlaybackService` and view models only.

**Tech Stack:** .NET 10, C#, WPF, xUnit, CommunityToolkit.Mvvm, Microsoft.Data.Sqlite, H.NotifyIcon.Wpf, libmpv-2.dll (P/Invoke), yt-dlp.exe, deno.exe, Windows SMTC via `Windows.Media.Playback`-free `SystemMediaTransportControls` interop (TFM `net10.0-windows10.0.19041.0`).

**Spec:** `docs/superpowers/specs/2026-11-15-native-music-design.md`

## Global Constraints

- Windows 10/11 x64 only; TFM `net10.0` (Core/tests), `net10.0-windows10.0.19041.0` (App, `UseWPF=true`).
- No browser engine anywhere (no WebView2/CEF/Electron packages).
- Anonymous only: no cookies, no Google login. InnerTube requests use `hl=en`, `gl=NP`.
- Network destinations allowed: `music.youtube.com`, `*.googlevideo.com` / `*.ytimg.com` / `*.ggpht.com` / `*.googleusercontent.com` (streams, art), `sponsor.ajay.app` (only when SponsorBlock on), `github.com` / `objects.githubusercontent.com` (tool downloads/updates). Nothing else.
- Data dir: `%LOCALAPPDATA%\Tune\` — `tune.db` (SQLite), `art\` (art cache, cap 200 MB, LRU delete), `tools\` (`yt-dlp.exe`, `deno.exe`), `logs\tune.log` (cap 1 MB, 1 rollover).
- Soft RAM target ≤ 120 MB working set for `Tune.exe` while playing; report actual, plus yt-dlp/deno separately. Helper processes: one resolve per play + one look-ahead, never more.
- yt-dlp update check at most once per 24 h on startup, plus once on a playback failure.
- SponsorBlock: category `music_offtopic` only, default ON, setting key `sponsorblock.enabled`.
- Theme: base `#121212`, sidebar `#000000`, cards `#181818` (hover `#282828`), text `#FFFFFF`, secondary `#B3B3B3`, accent `#1DB954`; font `Segoe UI Variable Text` (fallback `Segoe UI`, Devanagari via `Nirmala UI`).
- Parsers fail soft: an unparseable item/shelf is skipped and logged, never thrown to UI.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Unplayable song** (removed, region-blocked, age-restricted, yt-dlp error) → toast "Couldn't play <title> — skipped", advance to next; after 3 consecutive failures stop and show the error. Test in Task 9.
2. **Expired stream URL** (paused > URL `expire` time, laptop slept overnight) → on resume, re-resolve and seek to saved position instead of erroring. Test in Task 9.
3. **YouTube response shape changes** (a renderer type we don't know, missing fields) → that item/shelf is skipped, rest renders. Tests in Tasks 3–4 (`Unknown_renderer_is_skipped`, `Missing_thumbnail_still_parses`).
4. **Window positions on a monitor that's gone** (user runs MonitorSwapper/Sunshine; displays change) → main window and mini-player clamped onto a visible work area on restore. Test in Task 12 (`ClampToWorkArea`).
5. **No network at startup / mid-session** → Home shows "You're offline" with Retry, local playlists/Liked still browsable, no crash. Tests in Task 6 (`Discovery_failure_still_returns_local_shelves`) and Task 9.
